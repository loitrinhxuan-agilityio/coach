## The quality gates

As proposed, and **not approved**:

1. Required automated tests pass.
2. The UI conforms to the approved design.
3. An independent reviewer approves the change.

They stay proposals until they are reviewed and approved. Item 6 no longer comes first — CI exists, and
since change 9010 the review gate can actually fail. **One thing still comes first: the checks are
advisory until they are required on `main`.** That is a branch-protection setting, not a file, so it is
the Owner's to set, and approving the gates before it is set records an intention rather than a control.

The order that matters, because the second step is what tells you the first one worked:

1. The gate can block — done (change 9010).
2. **Watch one pull request carrying a real finding go red.** It has not happened yet; every run since
   the step landed has found nothing, so only the pass path has been exercised live.
3. Then require the checks on `main`.

Requiring a check nobody has seen fail is a milder version of the defect 9010 fixed.
